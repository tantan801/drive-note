# 第一章 字符设备驱动开发

本章先以一个虚拟的设备为例子讲解如何进行字符设备驱动开发，并且编写测试 APP 测试驱动工作是否异常。

---

## 1.1 字符设备驱动简介

字符设备是 Linux 驱动中最基本的设备驱动，即一个一个字节按字节流进行读写操作的设备，读写数据分先后顺序。例如点灯、按键、IIC、SPI、LCD 等都是字符设备。

在学习前得先了解如何调用驱动程序的调用，如图 1-1 所示：

![图1-1 Linux 应用程序对驱动程序的调用流程](photo/字符设备驱动入门/1-1%20系统运行流程.jpg)

在 Linux 中一切皆为文件，驱动加载成功后会在 `/dev` 目录下生成相应文件，应用程序通过对这个名为 `/dev/xxx`（xxx 是具体的驱动文件名字）的文件进行相应操作即可对硬件操作。

比如现在这个叫做 `/dev/led` 的驱动文件：

- 使用 `close` 函数关闭 `/dev/led` 这个文件
- `open` 和 `close` 就是打开和关闭 led 驱动的函数
- 如果要点亮或者关闭 led，那么就是用 `write` 函数来操作，向此驱动写入数据，这个数据就是要关闭或打开 led 的控制参数
- 如果要获取 LED 灯的状态就用 `read` 函数从驱动中读取状态

应用程序运行在**用户空间**；驱动属于内核一部分，运行在**内核空间**；用户空间不能直接访问内核，依靠系统调用完成切换。`open`、`close`、`write` 和 `read` 等这些函数是由 C 库提供的，在 Linux 系统中，系统调用作为 C 库的一部分。当我们调用 `open` 函数的时候流程如图：

![图1-2 系统调用流程](photo/字符设备驱动入门/1-2%20系统调用.jpg)

关于 C 库我们重点关注的是应用程序和具体的驱动，应用程序使用到的函数在具体驱动程序中都有与之对应的函数，比如应用程序中调用了 `open` 这个函数，那么在驱动程序中也得有一个名为 `open` 的函数。每一个系统调用，在驱动中都有与之对应的一个驱动函数。

在 Linux 内核文件 `include/linux/fs.h` 中有个叫做 `file_operations` 的结构体，此结构体就是 Linux 内核驱动操作函数集合：

| 成员 | 作用 |
|------|------|
| `owner` | 指向所属模块，一般填 `THIS_MODULE` |
| `llseek` | 修改文件读写偏移位置 |
| `read` | 对应应用 `read()`，从设备读取数据 |
| `write` | 对应应用 `write()`，向设备写数据 |
| `poll` | 轮询，用于非阻塞读写 |
| `unlocked_ioctl` | 对应应用 `ioctl()`，设备自定义控制命令；64 位系统 |
| `compat_ioctl` | 64 位内核，32 位应用程序调用 ioctl 时使用 |
| `mmap` | 将内核设备内存映射到用户空间，LCD 帧缓冲常用，减少数据拷贝 |
| `open` | 对应应用 `open()`，打开设备文件 |
| `release` | 对应应用 `close()`，关闭 / 释放设备文件 |

> 字符设备驱动不需要全部实现所有回调函数，根据硬件需求实现即可；基础驱动一般至少实现：`open`、`release`、`read`、`write`。

## 1.2 字符设备驱动开发步骤

Linux 驱动开发不只是操作寄存器，重点要遵守内核驱动框架。

### 1.2.1 驱动模块的加载和卸载

Linux 驱动有两种运行方式：

- **编译进内核**：内核启动的时候自动运行驱动
- **编译为内核模块（.ko）**：内核启动后手动加载；调试阶段优先使用
  - 优点：修改驱动只编译模块，不用完整编译整个内核，不用重启板子
  - 产品稳定后，可选择编译进内核，也可以继续使用 ko 模块

**模块入口、出口函数标记宏：**

```c
/* 驱动入口函数，__init：标记初始化函数，内核启动后可释放该段内存 */
static int __init xxx_init(void)
{
    /* 模块加载时执行的代码 */
    return 0;
}

/* 驱动出口函数，__exit：标记卸载函数 */
static void __exit xxx_exit(void)
{
    /* 模块卸载时执行的代码 */
}

// 注册：insmod 调用 xxx_init；rmmod 调用 xxx_exit
module_init(xxx_init);
module_exit(xxx_exit);
```

- `__init`：修饰初始化函数；内核启动完成后该段内存可以被释放
- `__exit`：修饰卸载函数；驱动编译进内核时，该函数会被丢弃
- `module_init(xxx_init)`：指定模块加载入口
- `module_exit(xxx_exit)`：指定模块卸载出口

驱动编译后扩展名为 `.ko`。

**ko 模块操作命令：**

| 命令 | 作用 | 特点 |
|------|------|------|
| `insmod xxx.ko` | 加载模块 | 不会处理模块依赖，依赖模块需要手动先加载 |
| `modprobe xxx` | 加载模块 | 自动解析并加载依赖模块；默认从 `/lib/modules/内核版本号/` 查找模块 |
| `rmmod xxx` | 卸载模块 | 推荐使用 |
| `modprobe -r xxx` | 卸载模块 | 会尝试卸载依赖模块，依赖被占用时卸载失败 |

> 自制 rootfs 一般没有 `/lib/modules` 目录，使用 modprobe 需要手动创建该目录。

### 1.2.2 字符设备注册与注销

在模块 `xxx_init` 里面注册字符设备；模块 `xxx_exit` 里面注销字符设备。

**函数原型：**

```c
// 注册字符设备
static inline int register_chrdev(unsigned int major, const char *name, const struct file_operations *fops);

// 注销字符设备
static inline void unregister_chrdev(unsigned int major, const char *name);
```

**`register_chrdev` 参数说明：**

1. `major`：**主设备号**；Linux 设备由主设备号、次设备号组成；`cat /proc/devices` 查看系统已占用主设备号，选用未被占用的
2. `name`：字符设备名字
3. `fops`：`struct file_operations *`，设备操作函数集合指针

**`unregister_chrdev` 参数说明：**

- `major`：要注销的主设备号
- `name`：设备名字

**模板示例代码：**

```c
// 定义操作函数集合变量，后续填充 open/release/read/write 回调
static struct file_operations test_fops;

/* 驱动入口函数 */
static int __init xxx_init(void)
{
    int retvalue = 0;

    /* 注册字符设备驱动，主设备号 200，名字 chrtest */
    retvalue = register_chrdev(200, "chrtest", &test_fops);
    if(retvalue < 0){
        // 注册失败错误处理
    }
    return 0;
}

/* 驱动出口函数 */
static void __exit xxx_exit(void)
{
    // 注销字符设备
    unregister_chrdev(200, "chrtest");
}

module_init(xxx_init);
module_exit(xxx_exit);
```

**查看系统已使用主设备号命令：**

```bash
cat /proc/devices
```

`file_operations` 结构体存放设备操作回调函数，需要自己实现对应回调函数，再对结构体初始化赋值。

**示例需求：**

| `chrtest_write` | 和 read 类似，把用户空间数据写到驱动 |
| `chrtest_release` | 应用 `close()` 关闭设备文件时调用 |

- `.owner = THIS_MODULE`：标记属于本驱动模块

- `MODULE_AUTHOR()`：作者信息，可选


## 1.3 Linux 设备号

### 1.3.1 设备号的组成

Linux 每一个设备都拥有设备号，**设备号 = 主设备号 + 次设备号**

- **主设备号**：标识对应的驱动程序；同一个驱动可以管理多个设备
- **次设备号**：区分同一个驱动下的不同设备

数据类型：`dev_t`，定义在 `include/linux/types.h`

```c
typedef __kernel_dev_t dev_t;
```

`__kernel_dev_t` 本质就是 `unsigned int`（32 位无符号整数）：

```c
typedef unsigned int __u32;
```

**32 位 bit 分配：** 高 12 位 = 主设备号；低 20 位 = 次设备号

主设备号范围：`0 ~ 4095`，写代码主设备号不能超出此区间。

头文件 `include/linux/kdev_t.h` 提供设备号操作宏：

| 宏 | 功能 |
|------|------|
| `MAJOR(dev)` | 从 dev_t 取出主设备号 |
| `MINOR(dev)` | 从 dev_t 取出次设备号 |
| `MKDEV(ma,mi)` | 主设备号 ma、次设备号 mi，合并生成 dev_t 完整设备号 |

源码定义：

```c
#define MINORBITS 20                           // 次设备号占 20 bit
#define MINORMASK ((1U << MINORBITS) - 1)      // 次设备号掩码
#define MAJOR(dev) ((unsigned int) ((dev) >> MINORBITS))          // 从 dev_t 提取主设备号
#define MINOR(dev) ((unsigned int) ((dev) & MINORMASK))           // 从 dev_t 提取次设备号
#define MKDEV(ma,mi) (((ma) << MINORBITS) | (mi))                 // 主、次设备号合成 dev_t
```

### 1.3.2 设备号的分配

#### 1）静态分配

开发者自己手动指定主设备号，例如直接写死 200。

- 参考内核文档：`Documentation/devices.txt`，里面记录内核已经预分配的设备号
- 查看开发板当前已经占用的主设备号命令：

```bash
cat /proc/devices
```

> 缺点：容易发生设备号冲突；内核社区不推荐静态分配。

#### 2）动态分配设备号

内核自动分配一个未被占用的主设备号，避免冲突。

**申请设备号函数 `alloc_chrdev_region()`：**

```c
int alloc_chrdev_region(dev_t *dev, unsigned baseminor, unsigned count, const char *name);
```

参数说明：

- `dev`：输出参数，保存申请成功之后生成的 dev_t 设备号
- `baseminor`：次设备号起始编号，一般填 0，次设备号从 0 开始
- `count`：申请连续设备号的数量
- `name`：设备名称

**释放设备号函数 `unregister_chrdev_region()`：**

卸载驱动时，释放之前动态申请的设备号：

```c
void unregister_chrdev_region(dev_t from, unsigned count);
```

- `from`：要释放的起始 dev_t 设备号
- `count`：释放连续设备号的个数

> 静态分配：直接 `MKDEV(ma,mi)` 构造 dev_t；动态分配：调用 `alloc_chrdev_region` 由内核分配，不能自己硬编码主设备号。

## 1.4 chrdevbase 字符设备驱动开发实验

字符设备驱动开发的基本步骤我们已经了解了，本节我们就以 **chrdevbase** 这个虚拟设备为例，完整的编写一个字符设备驱动模块。chrdevbase 不是实际存在的一个设备，是为了讲解字符设备开发而引入的一个虚拟设备，chrdevbase 设备有两个缓冲区，一个为读缓冲区、一个为写缓冲区，这两个缓冲区大小都是 100 字节。在应用程序中可以向 chrdevbase 设备的写缓冲中写入数据，从读缓冲区中读取数据。chrdevbase 的例程虽然简单但包含了字符设备的最基本功能。

### 1.4.1 实验程序编写

#### 2）chrdevbase.c 驱动源码

```c
#include <linux/types.h>
#include <linux/kernel.h>
#include <linux/delay.h>
#include <linux/ide.h>
#include <linux/init.h>
#include <linux/module.h>

#define CHRDEVBASE_MAJOR 200           /* 主设备号 */
#define CHRDEVBASE_NAME "chrdevbase"   /* 设备名  */

static char readbuf[100];           /* 读缓冲区 */
static char writebuf[100];          /* 写缓冲区 */
static char kerneldata[] = {"kernel data!"};

/*
 * @description : 打开设备
 * @param – inode : 传递给驱动的 inode
 * @param - filp  : 设备文件，file 结构体 private_data 一般保存设备结构体
 * @return        : 0 成功;其他 失败
 */
static int chrdevbase_open(struct inode *inode, struct file *filp)
{
    //printk("chrdevbase open!\r\n");
    return 0;
}

/*
 * @description : 从设备读取数据
 * @param - filp  : 要打开的设备文件(文件描述符)
 * @param - buf   : 返回给用户空间的数据缓冲区（__user 用户空间指针）
 * @param - cnt   : 要读取的数据长度
 * @param - offt  : 相对于文件首地址的偏移
 * @return        : 读取的字节数，如果为负值，表示读取失败
 */
static ssize_t chrdevbase_read(struct file *filp, char __user *buf, size_t cnt, loff_t *offt)
{
    int retvalue = 0;

    /* 向用户空间发送数据 */
    memcpy(readbuf, kerneldata, sizeof(kerneldata));
    retvalue = copy_to_user(buf, readbuf, cnt);
    if(retvalue == 0){
        printk("kernel senddata ok!\r\n");
    }else{
        printk("kernel senddata failed!\r\n");
    }
    return 0;
}

/*
 * @description : 向设备写数据
 * @param - filp  : 设备文件，表示打开的文件描述符
 * @param - buf   : 要写给设备写入的数据（用户空间）
 * @param - cnt   : 要写入的数据长度
 * @param - offt  : 相对于文件首地址的偏移
 * @return        : 写入的字节数，如果为负值，表示写入失败
 */
static ssize_t chrdevbase_write(struct file *filp, const char __user *buf, size_t cnt, loff_t *offt)
{
    int retvalue = 0;

    /* 接收用户空间传递给内核的数据并且打印出来 */
    retvalue = copy_from_user(writebuf, buf, cnt);
    if(retvalue == 0){
        printk("kernel recevdata:%s\r\n", writebuf);
    }else{
        printk("kernel recevdata failed!\r\n");
    }
    return 0;
}

/*
 * @description : 关闭/释放设备
 * @param - filp  : 要关闭的设备文件(文件描述符)
 * @return        : 0 成功;其他 失败
 */
static int chrdevbase_release(struct inode *inode, struct file *filp)
{
    //printk("chrdevbase release！\r\n");
    return 0;
}

/* 设备操作函数结构体 */
static struct file_operations chrdevbase_fops = {
    .owner   = THIS_MODULE,
    .open    = chrdevbase_open,
    .read    = chrdevbase_read,
    .write   = chrdevbase_write,
    .release = chrdevbase_release,
};

/*
 * @description : 驱动入口函数
 * @param       : 无
 * @return      : 0 成功;其他 失败
 */
static int __init chrdevbase_init(void)
{
    int retvalue = 0;

    /* 注册字符设备驱动 */
    retvalue = register_chrdev(CHRDEVBASE_MAJOR, CHRDEVBASE_NAME, &chrdevbase_fops);
    if(retvalue < 0){
        printk("chrdevbase driver register failed\r\n");
    }
    printk("chrdevbase_init()\r\n");
    return 0;
}

/*
 * @description : 驱动出口函数
 * @param       : 无
 * @return      : 无
 */
static void __exit chrdevbase_exit(void)
{
    /* 注销字符设备驱动 */
    unregister_chrdev(CHRDEVBASE_MAJOR, CHRDEVBASE_NAME);
    printk("chrdevbase_exit()\r\n");
}

module_init(chrdevbase_init);
module_exit(chrdevbase_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("tantan");
```

#### 3）printk 日志级别

`chrdevbase_open` 函数中我们没有做任何工作，只是输出一串字符，用于调试。这里使用了 `printk` 来输出信息，而不是 `printf`！因为在 Linux 内核中没有 `printf` 这个函数。`printk` 相当于 `printf` 的孪生兄妹，`printf` 运行在用户态，`printk` 运行在内核态。不同之处在于，`printk` 可以根据日志级别对消息进行分类，一共有 8 个消息级别，定义在 `include/linux/kern_levels.h`：

```c
#define KERN_SOH "\001"
#define KERN_EMERG   KERN_SOH "0"    /* 紧急事件，一般是内核崩溃    */
#define KERN_ALERT   KERN_SOH "1"    /* 必须立即采取行动          */
#define KERN_CRIT    KERN_SOH "2"    /* 临界条件，比如严重的软件或硬件错误 */
#define KERN_ERR     KERN_SOH "3"    /* 错误状态，一般设备驱动程序中使用 KERN_ERR 报告硬件错误 */
#define KERN_WARNING KERN_SOH "4"    /* 警告信息，不会对系统造成严重影响 */
#define KERN_NOTICE  KERN_SOH "5"    /* 有必要进行提示的一些信息  */
#define KERN_INFO    KERN_SOH "6"    /* 提示性的信息              */
#define KERN_DEBUG   KERN_SOH "7"    /* 调试信息                  */
```

> 数字越小，优先级越高。

#### 关键内核 API 说明

| API | 说明 |
|-----|------|
| `printk()` | 内核打印函数，替代用户态 `printf`，支持日志级别 |
| `copy_to_user(to, from, n)` | 内核 → 用户空间拷贝数据；`to` 是用户空间地址。返回 0 拷贝成功 |
| `copy_from_user(to, from, n)` | 用户 → 内核空间拷贝数据；`from` 是用户空间地址。返回 0 拷贝成功 |
| `filp->private_data` | `file` 结构体成员，`open` 回调里面常用来保存设备结构体 |

> **内核代码不能直接访问用户空间指针，必须使用这两个拷贝函数。**

### 1.4.2 编写测试 APP（chrdevbaseApp.c）

应用层系统调用：`open / read / write / close`

```c
#include "stdio.h"
#include "unistd.h"
#include "sys/types.h"
#include "sys/stat.h"
#include "fcntl.h"
#include "stdlib.h"
#include "string.h"

static char usrdata[] = {"usr data!"};

int main(int argc, char *argv[])
{
    int fd, retvalue;
    char *filename;
    char readbuf[100], writebuf[100];

    if(argc != 3){
        printf("Error Usage!\r\n");
        return -1;
    }

    filename = argv[1];

    /* 打开驱动设备文件，读写模式 */
    fd = open(filename, O_RDWR);
    if(fd < 0){
        printf("Can't open file %s\r\n", filename);
        return -1;
    }

    if(atoi(argv[2]) == 1){ /* 读设备 */
        retvalue = read(fd, readbuf, 50);
        if(retvalue < 0){
            printf("read file %s failed!\r\n", filename);
        }else{
            printf("read data:%s\r\n",readbuf);
        }
    }

    if(atoi(argv[2]) == 2){ /* 写设备 */
        memcpy(writebuf, usrdata, sizeof(usrdata));
        retvalue = write(fd, writebuf, 50);
        if(retvalue < 0){
            printf("write file %s failed!\r\n", filename);
        }
    }

    /* 关闭设备 */
    retvalue = close(fd);
    if(retvalue < 0){
        printf("Can't close file %s\r\n", filename);
        return -1;
    }

    return 0;
}
```

**APP 使用格式：**

```bash
# 读设备：参数 1
./chrdevbaseApp /dev/chrdevbase 1

# 写设备：参数 2
./chrdevbaseApp /dev/chrdevbase 2
```

**用户层文件函数原型：**

| 函数 | 原型 | 说明 |
|------|------|------|
| `open` | `int open(const char *pathname, int flags)` | 打开设备，`O_RDWR` 读写模式；返回文件描述符 `fd` |
| `read` | `ssize_t read(int fd, void *buf, size_t count)` | 从 `fd` 读取数据到 `buf` |
| `write` | `ssize_t write(int fd, const void *buf, size_t count)` | 把 `buf` 数据写入 `fd` |
| `close` | `int close(int fd)` | 关闭文件描述符 |
